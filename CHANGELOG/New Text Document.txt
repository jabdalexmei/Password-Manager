### Фиксация текста в кнопках навигации при изменении счётчика (`folder-count`)

### Краткое резюме
Сейчас текст сдвигается, потому что ширина правого счётчика меняется (`0` vs `71`), и блок имени пересчитывает доступное место.  
Решение: для кнопок со счётчиком сделать отдельный layout с симметричным резервом под число справа и «пустым» резервом слева, чтобы текст оставался строго по центру и не съезжал.  
По вашему выбору применяем везде, где есть `folder-count`, и резервируем `6` символов.

### Важные изменения в API/интерфейсах/типах
1. Публичные API, backend и типы не меняются.
2. Изменения только в UI (`tsx` + `css`) секций sidebar.
3. Добавляется только CSS-модификатор для кнопок со счётчиком, без изменения бизнес-логики.

### Детальный план реализации
1. Пометить кнопки со счётчиком отдельным классом-модификатором `vault-folder--with-count`.
2. Добавить этот класс в `src/features/Vault/components/Sidebar/sections/CategorySection.tsx` для обеих кнопок категорий.
3. Добавить этот класс в `src/features/Vault/components/Sidebar/sections/NavigationSection.tsx` для всех system-item кнопок.
4. Добавить этот класс в `src/features/Vault/components/Sidebar/sections/FoldersTreeSection.tsx` для кнопки папки (там, где рендерится `folder-count`).
5. В `src/shared/styles/screens/vault/sidebar.css` добавить стиль для `.vault-folder--with-count` с grid-раскладкой:
6. Использовать симметричные колонки: `6ch` слева (пустой резерв), `1fr` по центру (текст), `6ch` справа (счётчик).
7. Для `.vault-folder--with-count .folder-name` задать `grid-column: 2` и `text-align: center`.
8. Для `.vault-folder--with-count .folder-count` задать `grid-column: 3`, `width: 6ch`, `text-align: right`, `font-variant-numeric: tabular-nums`.
9. Для `.vault-folder--with-count` явно переопределить унаследованное поведение `flex` (через `display: grid`) и сбросить влияние `justify-content: space-between`, чтобы позиционирование было детерминированным.
10. Не менять стили `.vault-folder` для элементов без счётчика (например, список vault-ов), чтобы не затронуть их текущий вид.

### Тест-кейсы и сценарии
1. Проверка проблемы из скриншота: в категории `Карточка данных` переключение счётчика `0 -> 71` не двигает текст.
2. Проверка больших чисел: `9 -> 99 -> 999 -> 9999` не двигает текст.
3. Проверка значения длиннее резерва (`1000000`): текст остаётся фиксированным по центру; поведение счётчика остаётся предсказуемым.
4. Проверка `CategorySection`, `NavigationSection`, `FoldersTreeSection`: одинаковое поведение везде, где есть `folder-count`.
5. Проверка элементов без счётчика (`VaultsSection`): визуально без изменений.
6. Проверка длинных названий: ellipsis у `folder-name` сохраняется.
7. Проверка активного/hover/focus состояния кнопок: стили выбора и фокуса не ломаются.
8. Статическая проверка: `npm.cmd run typecheck`.

### Явные допущения и выбранные defaults
1. Scope фиксирован по вашему выбору: правка применяется везде, где есть `folder-count`.
2. Размер резерва фиксирован по вашему вводу: `6ch`.
3. «Текст по центру» трактуется как геометрический центр кнопки с симметричным резервом слева/справа.
4. Логика подсчёта и источники данных счётчиков не изменяются.
